# Besik — пользовательский магазин

React + TypeScript + Vite, обычный CSS. Без Tailwind, UI-фреймворков и административных экранов.

## Запуск

Нужен Node.js 22.14 или новее.

```sh
npm install
npm run dev
```

Магазин: http://127.0.0.1:5173. Backend по умолчанию: http://localhost:3000/api.
Vite проксирует `/api`, поэтому для локальной разработки не нужно менять CORS на backend.

Демонстрация без backend: http://127.0.0.1:5173/?demo=1. Демо включается только явно, имеет отдельные корзину и избранное и не отправляет заказы. Ошибки реального API не подменяются выдуманными товарами.

При необходимости скопируйте `.env.example` в `.env.local`. `API_PROXY_TARGET` задаёт адрес backend для dev/preview, `VITE_API_URL` — базовый URL API, включаемый в сборку. При размещении `dist` на сервере настройте reverse proxy `/api` на backend либо задайте абсолютный `VITE_API_URL` и разрешите origin магазина в CORS backend. Не размещайте секреты в переменных `VITE_*`.

```sh
npm run build
npm run preview
npm test
npm run format
```

## Возможности

- Адаптивная витрина и каталог, категории с учётом вложенности.
- Левое меню с категориями, избранным, корзиной и информацией о магазине. На мобильных экранах открывается как боковая панель с закрытием по Escape и по нажатию вне панели.
- Языки EN / KA / RU: интерфейс, карточки, корзина и оформление. Выбранный язык хранится в `localStorage` независимо от деморежима. Переключение не сбрасывает корзину, избранное или фильтры.
- Поиск по названию, описанию, бренду и SKU; сортировка по новизне, цене и названию; фильтр наличия.
- Отдельная карточка каждого активного варианта с характеристиками, ценой и остатком.
- Избранное и корзина сохраняются в localStorage. Фильтры сохраняются в URL, работают назад/вперёд.
- Гостевой заказ с доставкой или самовывозом через `POST /orders`.
- Повторная проверка цен и наличия перед заказом, блокировка повторного клика, обработка ошибок, подтверждение номера и суммы заказа.
- Количества дробных единиц меняются по 0,1, штучных — по 1. BIGINT ID остаются строками. Количество отправляется строкой, цену вычисляет backend.

## Структура

- `src/App.tsx` — композиция витрины и навигация.
- `src/components/` — карточка товара, подробности, общий диалог и корзина с оформлением.
- `src/lib/api.ts` — HTTP-клиент и используемые endpoint-ы.
- `src/lib/catalog.ts` — поиск, категории, сортировка, локализация, цены и остатки.
- `src/lib/cart.ts` — расчёт и проверка корзины.
- `src/lib/checkout.ts` — проверка контактов и формирование заказа по контракту API.
- `src/hooks/useStore.ts` — загрузка каталога и сохранение состояния.
- `src/hooks/useLanguage.tsx` — состояние языка, сохранение выбора и форматирование данных.
- `src/lib/translations.ts` — словарь интерфейса на английском и грузинском; русский — исходный язык. Динамические значения передаются через плейсхолдеры.
- `src/types.ts` — типы контракта backend.
- `src/data/demo.ts` — демонстрационные данные, динамически загружаются только в деморежиме.
- `src/styles.css` — стили и адаптивные размеры.
- `src/lib/store.test.ts` — тесты бизнес-логики.

## Подключение данных

Используются `GET /products`, `/categories`, `/product-variants/active`, `/units`, `/inventory/available` и `POST /orders`. Каталог строится по `/product-variants/active`: каждый вариант становится отдельной карточкой. Общие данные подставляются из `/products` по `productId`: описание, категория, бренд, дата создания; название варианта имеет приоритет для каждого заполненного языка, характеристики варианта дополняют и переопределяют характеристики товара. Статус товара временно не ограничивает показ: активные варианты товаров со статусом draft также отображаются. Проверки активности категории, варианта и единицы измерения сохранены. Поиск, цена, наличие и избранное работают для отдельных вариантов. Избранное вариантов хранится отдельно от прежнего избранного товаров. Названия и описания берутся из выбранного языка `nameI18n` / `descriptionI18n`. При отсутствующем или пустом переводе используется ru → en → ka. Произвольный текст backend не переводится автоматически: переводы товаров нужно заполнить в административной панели. Поиск учитывает все доступные языки, сортировка по названию — выбранный язык.

Фотографии вариантов запрашиваются через `GET /product-variants/:id/images`, файлы — через `GET /images/:filename` с базовым адресом `VITE_API_URL`. Ответ — массив `ProductVariantImage` с полями `id`, `productVariantId`, `imageUrl`, в порядке backend (`id ASC`). Используется `imageUrl`: абсолютные HTTP(S) ссылки сохраняются, пути `/images/...` и `images/...` разрешаются относительно `VITE_API_URL`, пути с префиксом `/api/...` — относительно origin API без повторного префикса. В каталоге, подробностях и корзине показано фото конкретного варианта; в подробностях доступно переключение фотографий. Запросы списка кешируются на минуту, ошибки не блокируют каталог. При пустом списке или ошибке API используются HTTP(S) URL из `variant.attributes.imageUrl` / `product.attributes.imageUrl`, затем нейтральная заглушка. Загрузка файлов не реализована. Остальные простые значения `attributes` отображаются как характеристики. Для публичного сайта используйте HTTPS-изображения. Демофотографии и интерьерные баннеры загружаются с Unsplash; шрифты — Google Fonts, с системными fallback.

Все товары одного заказа должны иметь одну валюту. Цена доставки приходит только после создания заказа: текущий API не предоставляет предварительный расчёт. Для самовывоза контакты сохраняются в `customerNote`, а `deliveryAddress` не передаётся. Итоговая сумма всегда берётся из ответа backend.

Регистрация, вход, списание денег и изменение статусов платежей не реализованы: доступный API не содержит безопасного клиентского сценария авторизации или банковской оплаты. Магазин не создаёт фиктивные платежи. Адрес и расписание самовывоза, контакты и конкретные условия доставки нужно добавить после их согласования.

Полный каталог фильтруется на клиенте, поскольку в документированном API нет параметров поиска и пагинации. Для большого ассортимента нужно добавить серверный поиск/пагинацию; список вариантов backend ограничен 1000 записями.
