# Besik — пользовательский магазин

React + TypeScript + Vite, серверный рендеринг (SSR) на Node.js и обычный CSS. Каталог и товары приходят готовым HTML; JavaScript подключает корзину, избранное и другие интерактивные элементы.

## Запуск

Нужен Node.js 22.14 или новее.

```sh
npm install
npm run dev
```

Магазин: http://127.0.0.1:5174. Backend по умолчанию: http://localhost:3000/api.
Vite проксирует `/api`, поэтому для локальной разработки не нужно менять CORS на backend.

Демонстрация без backend: http://127.0.0.1:5174/?demo=1. Демо включается только явно, имеет отдельные корзину и избранное и не отправляет заказы. Ошибки реального API не подменяются выдуманными товарами.

При необходимости скопируйте `.env.example` в `.env.local`. `API_PROXY_TARGET` задаёт адрес backend для dev/preview, `VITE_API_URL` — базовый URL API, включаемый в сборку. При размещении `dist` на сервере настройте reverse proxy `/api` на backend либо задайте абсолютный `VITE_API_URL` и разрешите origin магазина в CORS backend. Не размещайте секреты в переменных `VITE_*`.

```sh
npm run build
npm run preview
npm test
npm run format
```

## Возможности

- Адаптивная витрина и каталог, категории с учётом вложенности.
- Левое меню с категориями, избранным, корзиной и информацией о магазине. На мобильных экранах открывается как боковая панель с закрытием по Escape и по нажатию вне панели.
- Языки EN / KA / RU: интерфейс, карточки, корзина и оформление. Выбранный язык хранится в `localStorage` независимо от деморежима. Переключение не сбрасывает корзину, избранное или фильтры.
- Поиск по названию, описанию, бренду и SKU; сортировка по новизне, цене и названию; фильтр наличия.
- Отдельная карточка каждого активного варианта с характеристиками, ценой и остатком.
- Отдельная серверная страница `/products/<slug>/<variantId>` для каждого варианта. Работают обновление, история, новая вкладка и просмотр без JavaScript. Устаревший slug перенаправляется на текущий с HTTP 308.
- SEO: серверные title/description, canonical, hreflang RU/EN/KA, Open Graph/Twitter, JSON-LD Product/BreadcrumbList, robots.txt и sitemap.xml. Каталог имеет доступную поисковикам пагинацию.
- Каталог, фотографии, избранное и корзина доступны без регистрации. Избранное и корзина сохраняются в localStorage. Фильтры сохраняются в URL, работают назад/вперёд.
- Кнопка «Войти» справа в шапке открывает отдельную страницу `/auth`: вход по логину, регистрация с подтверждением email, повторная отправка письма и Google OAuth. Доступные способы регистрации определяет backend через `/auth/options`.
- Заказ после входа с доставкой или самовывозом: покупатели используют `POST /me/orders`, admin/Root — `POST /orders`. Доступ дополнительно проверяет backend.
- Повторная проверка цен и наличия перед заказом, блокировка повторного клика, обработка ошибок, подтверждение номера и суммы заказа.
- Количества дробных единиц меняются по 0,1, штучных — по 1. BIGINT ID остаются строками. Количество отправляется строкой, цену вычисляет backend.

## Структура

- `src/App.tsx` — композиция витрины и навигация.
- `src/components/` — карточка товара, подробности, общий диалог и корзина с оформлением.
- `src/lib/api.ts` — HTTP-клиент и используемые endpoint-ы.
- `src/lib/catalog.ts` — поиск, категории, сортировка, локализация, цены и остатки.
- `src/lib/cart.ts` — расчёт и проверка корзины.
- `src/lib/checkout.ts` — проверка контактов и формирование заказа по контракту API.
- `src/hooks/useStore.ts` — загрузка каталога и сохранение состояния.
- `src/hooks/useLanguage.tsx` — состояние языка, сохранение выбора и форматирование данных.
- `src/lib/translations.ts` — словарь интерфейса на английском и грузинском; русский — исходный язык. Динамические значения передаются через плейсхолдеры.
- `src/types.ts` — типы контракта backend.
- `src/data/demo.ts` — демонстрационные данные, динамически загружаются только в деморежиме.
- `src/styles.css` — стили и адаптивные размеры.
- `src/lib/store.test.ts` — тесты бизнес-логики.

## Подключение данных

Используются `GET /products`, `/categories`, `/product-variants/active`, `/units`, `/inventory/available` и `POST /orders`. Каталог строится по `/product-variants/active`: каждый вариант становится отдельной карточкой. Общие данные подставляются из `/products` по `productId`: описание, категория, бренд, дата создания; название варианта имеет приоритет для каждого заполненного языка, характеристики варианта дополняют и переопределяют характеристики товара. Статус товара временно не ограничивает показ: активные варианты товаров со статусом draft также отображаются. Проверки активности категории, варианта и единицы измерения сохранены. Поиск, цена, наличие и избранное работают для отдельных вариантов. Избранное вариантов хранится отдельно от прежнего избранного товаров. Названия и описания берутся из выбранного языка `nameI18n` / `descriptionI18n`. При отсутствующем или пустом переводе используется ru → en → ka. Произвольный текст backend не переводится автоматически: переводы товаров нужно заполнить в административной панели. Поиск учитывает все доступные языки, сортировка по названию — выбранный язык.

Фотографии вариантов запрашиваются через `GET /product-variants/:id/images`, файлы — через `GET /images/:filename` с базовым адресом `VITE_API_URL`. Ответ — массив `ProductVariantImage` с полями `id`, `productVariantId`, `imageUrl`, в порядке backend (`id ASC`). Используется `imageUrl`: абсолютные HTTP(S) ссылки сохраняются, пути `/images/...` и `images/...` разрешаются относительно `VITE_API_URL`, пути с префиксом `/api/...` — относительно origin API без повторного префикса. В каталоге, подробностях и корзине показано фото конкретного варианта; в подробностях доступно переключение фотографий. Запросы списка кешируются на минуту, ошибки не блокируют каталог. При пустом списке или ошибке API используются HTTP(S) URL из `variant.attributes.imageUrl` / `product.attributes.imageUrl`, затем нейтральная заглушка. Загрузка файлов не реализована. Остальные простые значения `attributes` отображаются как характеристики. Для публичного сайта используйте HTTPS-изображения. Демофотографии и интерьерные баннеры загружаются с Unsplash; шрифты — Google Fonts, с системными fallback.

Все товары одного заказа должны иметь одну валюту. Цена доставки приходит только после создания заказа: текущий API не предоставляет предварительный расчёт. Для самовывоза контакты сохраняются в `customerNote`, а `deliveryAddress` не передаётся. Итоговая сумма всегда берётся из ответа backend.

Вход и выход используют `/auth/login`, `/auth/me`, `/auth/logout` и серверную HttpOnly-cookie. Все запросы включают `credentials: 'include'`, изменяющие запросы — `X-CSRF-Protection: 1`. Секреты сессии не сохраняются в браузерном хранилище. Каталог загружается независимо от проверки сессии. Гость может добавлять товары в корзину и менять количество; вход запрашивается при переходе к оформлению. Корзина сохраняется после обновления страницы, входа и выхода. При HTTP 401 во время оформления требуется повторный вход. После входа восстанавливаются фильтры каталога; при переходе из корзины она открывается повторно. Списание денег и изменение статусов платежей не реализованы. Адрес и расписание самовывоза, контакты и конкретные условия доставки нужно добавить после их согласования.

Для регистрации по email backend должен иметь настроенный SMTP. Задайте на backend `EMAIL_VERIFICATION_URL=https://<домен-магазина>/verify-email`: страница отправляет токен в `POST /auth/verify-email`, затем предлагает войти. Пароль содержит 12–128 символов, логин — 3–100 латинских букв, цифр и символов `_.@-`, как требует backend. Регистрация не создаёт сессию до подтверждения email.

Для Google OAuth настройте провайдера на backend и `AUTH_SUCCESS_URL=https://<домен-магазина>/auth`. Кнопка получает URL через `POST /auth/google/start`, а код и cookie обрабатывает backend в `/api/auth/google/callback`. Если Google требует подтверждения email, страница показывает соответствующее сообщение. `returnTo` допускает только каталог на том же origin; адрес возврата сохраняется в sessionStorage на время OAuth. Сервер frontend должен отдавать `index.html` для `/auth` и `/verify-email` (Vite и текущий Caddyfile уже это поддерживают). Backend-секреты не добавляйте в `VITE_*`.

Развёртывание SSR на VPS описано в [deploy/vps/README.md](deploy/vps/README.md). `npm run release:vps` создаёт ZIP с клиентской/серверной сборкой, Node-сервером, package-lock.json и Dockerfile. Настройки backend и секреты в архив не входят. Прежняя раздача одного index.html через SPA fallback для этой версии не подходит.

Публичный API возвращает списки без поиска/пагинации; SSR-сервис фильтрует кешированный каталог и отдаёт страницы по 12 вариантов. Список вариантов backend ограничен 1000 записями; для большего ассортимента нужна пагинация самого API.

## SSR и SEO

`npm run dev` использует SSR middleware Vite на 5174. `npm run build` собирает `dist/client` и `dist/server`; API во время сборки не нужен. `npm start` запускает production-сборку на 5174, `npm run preview` — на 4173. Для production нужны Node.js 22.14+, обязательный `SITE_URL` (публичный origin магазина) и `SERVER_API_URL` (внутренний URL API с `/api`). `SITE_URL` задаёт canonical, sitemap и публичные URL изображений. `SERVER_API_URL` не попадает в браузер; SSR не передаёт cookie или токены пользователя в публичный API. Ответы каталога кешируются на 30 секунд, списки изображений — на минуту.

Каждому SKU соответствует свой URL с нормализованным slug. Английский и грузинский используют `?lang=en` и `?lang=ka`, русский — основной адрес. Переключение языка ведёт на отдельный документ; предпочтение сохраняется в браузере. `/sitemap.xml` содержит публичные варианты на трёх языках и автоматически разбивается при росте каталога. Неизвестные товары/пути возвращают HTTP 404, сбой API — 503 с Retry-After; оба ответа содержат noindex. Поиск, избранное, фильтры и авторизация не индексируются. При сбое API sitemap тоже возвращает 503, а не пустой успешный ответ.

На странице товара отдельно показаны описание и характеристики из API. Product JSON-LD использует реальные имя, описание, SKU, бренд, фотографии и характеристики. Offer добавляется только при положительной цене и корректной валюте; нулевая цена-заглушка не рекламируется как бесплатный товар. Рейтинги, отзывы, доставка и правила возврата не добавляются без данных. Текст экранируется; JSON-LD и bootstrap-данные защищены от закрытия script-тега пользовательским текстом.

После публикации отправьте `/sitemap.xml` в Google Search Console и проверьте URL товара в URL Inspection / Rich Results Test. Разметка не гарантирует расширенный результат. Подход основан на [Vite SSR](https://vite.dev/guide/ssr), [рекомендациях Google для JavaScript-сайтов](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics) и [Product structured data](https://developers.google.com/search/docs/appearance/structured-data/product-snippet).
